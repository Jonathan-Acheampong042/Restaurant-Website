# Local Development & Testing Guide — Ember & Olive

This guide is for engineers developing and maintaining the **Ember & Olive** platform.

---

## 1. Prerequisites

- **Node.js**: `v22.0.0` or higher (required for native TypeScript `--experimental-strip-types` and `node:sqlite`).
- **npm**: `v10.0.0` or higher.
- **Git**: Installed and configured.

---

## 2. Quickstart

```bash
# 1. Install dependencies
npm install

# 2. Initialize the SQLite database and seed initial menu data
node --experimental-strip-types src/db/cli.ts init

# 3. Start the Backend API server (in terminal 1)
node --experimental-strip-types src/server/index.ts

# 4. Start the Vite Frontend development server (in terminal 2)
npm run dev
```

- Frontend Dev UI: `http://localhost:5173`
- Backend API Server: `http://localhost:3001`
- Backend Health Check: `http://localhost:3001/api/health`

---

## 3. Available npm Scripts

Defined in `package.json`:

| Command | Action |
|---|---|
| `npm run dev` | Starts the Vite development server with Hot Module Replacement (HMR). |
| `npm run build` | Builds the React frontend application into optimized static assets in `dist/`. |
| `npm run preview` | Runs a local web server serving the compiled `dist/` directory. |
| `npm run typecheck` | Runs the TypeScript compiler (`tsc --noEmit`) to validate type contracts. |
| `npm test` | Executes the frontend test suite using Node's test runner (`tests/frontend.test.ts`). |

## 4. Test Suites & Verification Commands

All test suites are automated and require no external test framework installations:

### 4.1 Frontend Test Suite
Validates reservation input constraints, dietary filtering logic, and API mock fallback behaviors:
```bash
npm test
```
*Output: 18 tests passing across 3 test suites.*

### 4.2 Backend Test Suite
Validates reservation input validation, SQLite and stub database adapters, and HTTP API route responses:
```bash
node tests/backend/run-tests.ts
```
*Output: 27 tests passing across 3 test suites.*

### 4.3 Database Test Suite
Validates schema migration idempotency, menu repository CRUD, reservation persistence across restart, and restaurant profile operations:
```bash
node --test src/db/tests/migration.test.ts src/db/tests/menu.test.ts src/db/tests/reservations.test.ts src/db/tests/restaurant.test.ts src/db/tests/persistence.test.ts
```
*Output: 5 tests passing across 5 suites.*

### 4.4 Full Quality Verification Sweep
Run all test suites and production build sequentially:
```bash
npm run typecheck
npm test
node tests/backend/run-tests.ts
node --test src/db/tests/migration.test.ts src/db/tests/menu.test.ts src/db/tests/reservations.test.ts src/db/tests/restaurant.test.ts src/db/tests/persistence.test.ts
npm run build
```

## 6. Architecture & Contract Guidelines

When modifying code, maintain contract alignment:
1. **Never alter shared interface signatures** (`types/shared.ts`) without updating `.team/CONTRACTS.md`.
2. **Preserve WCAG 2.1 AA Compliance**: All text colors must maintain at least 4.5:1 contrast against `#FAF8F5` linen background; interactive buttons must provide visible focus rings and 44x44px minimum tap targets.
3. **Database Migrations**: Add new migration files incrementally into `migrations/` with a numbered prefix (e.g. `003_xxx.sql`). Never modify already-applied migration files.
